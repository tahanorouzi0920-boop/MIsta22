# MISTA — سامانه مدیریت شرکت (میستا)

Mehrgasht Integrated Systems for Transport and Automation

## پیش‌نیاز

- **Node.js نسخه ۲۲.۱۳ یا بالاتر** (برای پایگاه‌داده داخلی `node:sqlite`). نسخه را با دستور زیر بررسی کنید:
  ```
  node -v
  ```
- هیچ پکیج npm خارجی لازم نیست؛ `npm install` لازم نیست.

## اجرا در VS Code

1. پوشه `mista` را در VS Code باز کنید (`File → Open Folder`).
2. ترمینال را باز کنید (`Terminal → New Terminal`) و دستور زیر را اجرا کنید:
   ```
   npm start
   ```
3. مرورگر را باز کنید و آدرس زیر را وارد کنید:
   ```
   http://127.0.0.1:3000
   ```

### ورود اولیه

- نام کاربری: `admin`
- رمز عبور پیش‌فرض: `Admin@12345`

رمز پیش‌فرض فقط برای نخستین راه‌اندازی است. قبل از استفاده واقعی آن را تغییر دهید، یا پیش از اولین اجرا متغیر `ADMIN_PASSWORD` را تنظیم کنید.

### تنظیمات (اختیاری)

می‌توانید این متغیرها را در ترمینال قبل از `npm start` تنظیم کنید:

| متغیر | معنی | پیش‌فرض |
|---|---|---|
| `PORT` | پورت سرور | `3000` |
| `HOST` | آدرس شنود | `127.0.0.1` |
| `ADMIN_USER` | نام کاربری مدیر اصلی (فقط اولین اجرا) | `admin` |
| `ADMIN_PASSWORD` | رمز مدیر اصلی (فقط اولین اجرا) | `Admin@12345` |
| `SESSION_IDLE_MINUTES` | مدت بی‌فعالیتی قبل از خروج خودکار | `30` |
| `MAX_UPLOAD_MB` | حداکثر حجم فایل مدرک | `5` |
| `MISTA_DATA_DIR` | پوشه داده‌ها (پایگاه‌داده و فایل‌ها) | `./data` |

در ویندوز PowerShell مثال تنظیم رمز اولیه:
```
$env:ADMIN_PASSWORD="Strong@Pass123"; npm start
```

## آزمون‌ها

```
npm test
```

آزمون‌ها سرور را با یک پایگاه‌داده موقت اجرا می‌کنند و مسیرهای اصلی را بررسی می‌کنند: ورود، اعتبارسنجی، کد ملی، پلاک، شماره قرارداد، قوانین تاریخ، دسترسی نقش‌ها، آپلود فایل، ممیزی و داشبورد.

## ساختار پروژه

```
server/
  index.js        نقطه ورود سرور HTTP و توزیع درخواست‌ها
  routes.js       همه مسیرهای API با اعتبارسنجی، دسترسی و ثبت ممیزی
  db.js           اتصال پایگاه‌داده، مهاجرت‌های نسخه‌دار و داده‌های اولیه
  lib.js          نشست، دسترسی، ممیزی، اعتبارسنجی، خواندن فرم چندبخشی
  reference.js    فهرست برندها، استان‌ها، نقش‌ها، دسترسی‌ها و کاتالوگ مدارک
  jalali.js       تبدیل و اعتبارسنجی تاریخ شمسی (سال ۱۳۵۰ تا ۱۴۱۰)
  crypto.js       هش رمز (scrypt) و توکن نشست
public/
  index.html      صفحه اصلی
  style.css       طراحی Glass / Dark / Light
  app.js          منطق رابط کاربری، تقویم شمسی و فرم‌ها
tests/
  api.test.js     آزمون‌های خودکار
data/             (ساخته می‌شود) پایگاه‌داده و فایل‌های مدارک
```

## ساختار منو (نهایی)

- **اطلاعات پایه:** شرکت‌ها
- **ترابری:** قرارداد خودرو
- **سلامت و ایمنی:** مدارک خودرو
- **مدیریت سیستم:** کاربران
- **گزارش** (مستقل، خارج از گروه‌ها)
- پروفایل و خروج (خارج از گروه‌ها)

صفحات رانندگان، خودروها، مدارک رانندگان و انواع مدارک از منو حذف شده‌اند. ثبت راننده و خودرو جدید از داخل فرم قرارداد انجام می‌شود و داده‌ها و APIهای آن‌ها باقی است.

## قوانین مدارک

- مالک هر مدرک فقط **راننده** یا **خودرو** است. مدارک شرکت دیگر ثبت نمی‌شوند؛ انواع مدارک شرکت (در صورت وجود در داده‌های قدیمی) غیرفعال شده‌اند ولی حذف نشده‌اند.
- بخش «مدارک رانندگان»: ابتدا راننده را جست‌وجو و انتخاب کنید؛ فقط مدارک همان راننده نمایش داده می‌شود.
- بخش «مدارک خودرو»: ابتدا خودرو را انتخاب کنید؛ فقط مدارک همان خودرو نمایش داده می‌شود.
- فرم مدرک فیلدهای «رکورد مرتبط»، «صادرکننده» و «شماره مدرک» را ندارد؛ مالک از بخش انتخاب‌شده تعیین می‌شود.
- ویرایش مشخصات مدرک فقط فیلدهای ارسال‌شده را تغییر می‌دهد.

## استان و شهر

- فهرست استان‌ها و شهرها در `server/reference.js` است و هم رابط کاربری و هم سرور از همین منبع استفاده می‌کنند.
- شهر هر شرکت باید متعلق به استان همان شرکت باشد؛ سرور این را بررسی و در صورت ناسازگاری ذخیره را رد می‌کند.
- **محدودیت:** فهرست فعلی فقط شامل ۳۱ استان و مراکز استان‌ها به‌همراه چند شهر نمونه است. فهرست کامل شهرهای رسمی باید از منبع رسمی به همان فایل اضافه شود؛ شناسه‌های پایدار استان و شهر هنوز اضافه نشده‌اند و تطبیق بر اساس نام انجام می‌شود.
- شرکت‌های جدید فقط می‌توانند کشور «ایران» داشته باشند؛ شرکت‌های قدیمی با کشور متفاوت بدون تغییر نگه داشته می‌شوند.

## انتشار روی Cloudflare (مهم)

بک‌اند MISTA یک فرایند Node.js همیشه‌فعال است و داده‌ها را در SQLite روی دیسک نگه می‌دارد. Cloudflare Pages فقط فایل‌های استاتیک را سرو می‌کند. اگر فقط پوشه `public/` منتشر شود، درخواست‌های `/api/login` و `/api/me` پاسخ **۴۰۴** می‌گیرند؛ این دقیقاً همان خطایی است که در کنسول دیده می‌شود.

روش پیشنهادی (بدون بازنویسی بک‌اند):
1. بک‌اند را روی یک سرویس Node.js با دیسک پایدار اجرا کنید (مثلاً یک VPS یا سرویس PaaS). دستور اجرا: `npm start` با `HOST=0.0.0.0` و `PORT` مناسب سرویس، و `MISTA_DATA_DIR` روی دیسک پایدار.
2. فایل `deploy/cloudflare/_redirects.example` را به `public/_redirects` کپی کنید و `YOUR-BACKEND-HOST` را با آدرس واقعی بک‌اند جایگزین کنید.
3. پروژه Pages را از پوشه `public/` منتشر کنید.

با این کار مرورگر فقط با دامنه Cloudflare ارتباط دارد و `/api/*` از طریق Cloudflare به بک‌اند هدایت می‌شود. کوکی نشست با `SameSite=Strict` روی همین دامنه ارسال می‌شود.

Pages Functions برای این بک‌اند مناسب نیست، چون بک‌اند از `node:sqlite` و نوشتن روی دیسک استفاده می‌کند که در Workers در دسترس نیست. تبدیل آن به D1 و R2 بازنویسی کامل بک‌اند است.

اگر `config.js` مقدار `MISTA_API_BASE` را روی دامنه دیگری قرار دهید، کوکی نشست ارسال نمی‌شود و ورود کار نمی‌کند؛ بنابراین مقدار آن را خالی نگه دارید و از پراکسی استفاده کنید.

## داده‌های جغرافیایی (استان و شهر)

- منبع داده: `server/geo/geo-data.json`. جزئیات منبع و وضعیت تکمیل در `server/geo/SOURCE.md` آمده است.
- هر استان کد پایدار `P01`..`P31` و هر شهر شناسه پایدار مانند `P07-001` دارد. این کدها هرگز بازشماری نمی‌شوند.
- فهرست شهرها **هنوز ناقص است**. برای تکمیل از `tools/import-geo.js` استفاده کنید (توضیح در SOURCE.md).
- شرکت‌ها و رانندگان با کد استان و شناسه شهر ذخیره می‌شوند؛ نام‌های قبلی تغییر نکرده‌اند.

## نقش‌ها و دسترسی

| نقش | دسترسی |
|---|---|
| مدیر سیستم | دسترسی کامل |
| مدیر | همه بخش‌ها؛ بدون حذف کاربر |
| کاربر عادی | شرکت، راننده، خودرو، قرارداد و مدارک (بدون حذف) |
| حسابرس | فقط مشاهده و گزارش‌ها |

دسترسی‌ها در سرور اعمال می‌شوند؛ مخفی‌کردن دکمه‌ها در مرورگر به‌تنهایی کافی نیست. مدیر اصلی قابل غیرفعال‌سازی، حذف یا تغییر نقش نیست.

## نکات امنیتی و محدودیت‌ها

- رمز عبور با `scrypt` هش می‌شود و هرگز در ممیزی یا پاسخ‌ها نمایش داده نمی‌شود.
- نشست در پایگاه‌داده ذخیره می‌شود و پس از مدت بی‌فعالیتی منقضی می‌شود.
- فایل‌های مدارک در `data/uploads` با نام تصادفی ذخیره می‌شوند و فقط از طریق API و با دسترسی کاربر مجاز قابل دانلود هستند. محتوای فایل (امضای PDF/JPG/PNG) بررسی می‌شود.
- بارگذاری فایل هرگز به‌معنی تأیید مدرک نیست؛ مدرک تا بررسی کاربر مجاز در وضعیت «نیازمند بررسی» می‌ماند.
- برای استفاده روی شبکه یا اینترنت باید HTTPS و یک پروکسی امن جلوی سرور قرار گیرد؛ پیش از آن، پشتیبان‌گیری از `data/` را فراموش نکنید.
- فهرست شهرها کامل نیست؛ فقط مراکز استان‌ها و چند شهر نمونه درج شده‌اند. فهرست برندها، مدل‌ها و کلاس‌های خودرو باید با منابع رسمی تطبیق داده شوند.
- نوار پیشرفت آپلود نمایش داده نمی‌شود.
- رانندگان و خودروها از «اطلاعات پایه» به بخش «ترابری» منتقل شده‌اند تا دسترسی به آن‌ها حفظ شود.
